# Модели и системные требования

БРОДЯГА по умолчанию использует две официальные модели из библиотеки Ollama:

- `qwen3:8b` — текст, reasoning, код и tool calling;
- `qwen3-vl:8b` — изображения, скриншоты, документы и OCR.

Обе модели в стандартных тегах Ollama имеют квантизацию Q4_K_M. Qwen 3 VL требует
Ollama 0.12.7+, а pinned-образ проекта новее этого минимума.

## Размеры и практические профили

| Профиль | LLM | Вес | VLM | Вес | Практический минимум памяти* |
|---|---|---:|---|---:|---:|
| Tiny | `qwen3:1.7b` | 1.4 ГБ | `qwen3-vl:2b` | ~1.9 ГБ | 8 ГБ RAM / 4 ГБ VRAM |
| Light | `qwen3:4b` | 2.5 ГБ | `qwen3-vl:4b` | 3.3 ГБ | 16 ГБ RAM / 6–8 ГБ VRAM |
| Default | `qwen3:8b` | 5.2 ГБ | `qwen3-vl:8b` | 6.1 ГБ | 32 ГБ RAM / 10–12 ГБ VRAM |
| Strong | `qwen3:14b` | 9.3 ГБ | `qwen3-vl:8b` | 6.1 ГБ | 32–48 ГБ RAM / 16 ГБ VRAM |
| Power | `qwen3:30b` | 19 ГБ | `qwen3-vl:30b` | 20 ГБ | 64 ГБ RAM / 24+ ГБ VRAM |

\* Оценка дана для одной активной модели, одного запроса и контекста около 32K.
Это не официальная гарантия: кроме весов, память занимает KV-cache, vision encoder,
runtime и буферы. Если не хватает VRAM, Ollama выгружает часть слоёв в RAM, но
скорость заметно падает.

Актуальные точные размеры тегов: [Qwen 3](https://ollama.com/library/qwen3) и
[Qwen 3 VL](https://ollama.com/library/qwen3-vl).

## Как выбрать

- **Ноутбук/мини-ПК без GPU:** начните с `--light`; 4B заметно быстрее на CPU.
- **8 ГБ VRAM:** 4B почти всегда комфортнее; 8B может потребовать короткого контекста.
- **12 ГБ VRAM:** стандартные 8B — разумный баланс.
- **16 ГБ VRAM:** Qwen 3 14B + VL 8B, если модели не держатся одновременно.
- **24 ГБ VRAM:** 30B Q4 обычно помещается впритык; оставьте запас под KV-cache.
- **Apple Silicon:** ориентируйтесь на общую unified memory и используйте native Ollama.

## RTX 3060 12 ГБ: без offload в RAM

RTX 3060 имеет compute capability 8.6 и поддерживается Ollama. Цель профиля —
держать веса и KV-cache одной модели в VRAM, не позволяя Ollama переносить слои в
оперативную память.

### Требования к компьютеру

| Компонент | Минимум | Рекомендуется | Комментарий |
|---|---:|---:|---|
| GPU | RTX 3060 12 ГБ | RTX 3060 12 ГБ с 10+ ГБ свободной VRAM | Монитор и другие приложения тоже занимают VRAM |
| NVIDIA driver | 531 | Актуальный стабильный | Проверяется командой `nvidia-smi` |
| Системная RAM | 16 ГБ | 32 ГБ | 16 ГБ достаточно при полном GPU-размещении, но запас небольшой |
| CPU | 4 ядра | 6+ ядер / 12 потоков | CPU не должен считать основные слои модели |
| Диск | 25 ГБ SSD | 40 ГБ SSD | Две модели, контейнеры, обновления и история чатов |
| ОС | Linux x86_64 / WSL2 | Ubuntu 24.04 LTS | Нужны Docker, Compose и NVIDIA Container Toolkit |

### Какие модели помещаются

| Модель | Вес Q4 | Для 3060 12 ГБ | Рекомендация |
|---|---:|---|---|
| `qwen3:4b` | 2.5 ГБ | С большим запасом | Максимальная скорость, длиннее контекст |
| `qwen3-vl:4b` | 3.3 ГБ | С большим запасом | Лёгкий vision/OCR |
| `qwen3:8b` | 5.2 ГБ | Да, одна модель | Основная LLM профиля |
| `qwen3-vl:8b` | 6.1 ГБ | Да, одна модель | Основная VLM профиля |
| `qwen3:14b` | 9.3 ГБ | Погранично | Только короткий контекст; если важен нулевой offload — не использовать |
| `qwen3:30b` | 19 ГБ | Нет | Не поместится целиком, уйдёт в RAM |

Веса — не вся VRAM: дополнительно нужны KV-cache, runtime и vision-буферы. Поэтому
две 8B-модели не следует держать одновременно, даже если сумма файлов близка к
12 ГБ.

### Запуск готового профиля

```bash
make rtx3060

# Для coding agent после установки Kimi Code:
make kimi-3060
```

Команда использует [`profiles/rtx3060-12gb.env.example`](../profiles/rtx3060-12gb.env.example)
и memory-limit overlay. Основные настройки:

```dotenv
OLLAMA_CONTEXT_LENGTH=16384
OLLAMA_MAX_LOADED_MODELS=1
OLLAMA_NUM_PARALLEL=1
OLLAMA_FLASH_ATTENTION=1
OLLAMA_KV_CACHE_TYPE=q8_0
OLLAMA_KEEP_ALIVE=0
OLLAMA_MEMORY_LIMIT=12g
WEBUI_MEMORY_LIMIT=4g
```

Flash Attention уменьшает расход памяти с ростом контекста. `q8_0` использует
примерно половину памяти KV-cache относительно `f16` с небольшой потерей точности.
`KEEP_ALIVE=0` выгружает модель сразу после ответа: следующий первый токен будет
медленнее, зато память не останется занятой в простое.

### Что проверить после запуска

Сделайте один запрос выбранной модели и сразу выполните:

```bash
make memory
```

Проверка считается успешной, когда:

1. `nvidia-smi` показывает все 12 ГБ VRAM и актуальный driver.
2. `ollama ps` показывает только одну модель и `PROCESSOR = 100% GPU`.
3. У модели контекст 16384, а не 32K/64K/256K.
4. `docker stats` остаётся ниже лимитов Ollama 12 ГБ и WebUI 4 ГБ.
5. В `free -h` смотрите на `available`, а не только на `used`: Linux учитывает
   освобождаемый файловый cache как занятую память.
6. Swap не растёт во время ответа: `watch -n 1 free -h`.

Для ручной проверки:

```bash
watch -n 1 nvidia-smi
docker compose -f compose.yaml exec ollama ollama ps
docker stats --no-stream
free -h
```

Если в `PROCESSOR` появляется `CPU/GPU`, действуйте в таком порядке:

1. закройте игры, браузеры с GPU acceleration и другие CUDA-процессы;
2. уменьшите `OLLAMA_CONTEXT_LENGTH` до `8192`;
3. убедитесь, что `OLLAMA_NUM_PARALLEL=1` и `OLLAMA_MAX_LOADED_MODELS=1`;
4. переключитесь с 8B на 4B;
5. пересоздайте Ollama: `make down && make up-3060`;
6. повторите запрос и `make memory`.

Важно: `100% GPU` не означает буквально 0 байт RAM. Процесс, Docker, сетевые
буферы, Open WebUI и отображение файлов модели всё равно требуют оперативной
памяти. Задача — исключить вычислительный offload весов модели в RAM.

## Сменить профиль

Отредактируйте `.env`:

```dotenv
QWEN_MODEL=qwen3:14b
VLM_MODEL=qwen3-vl:8b
OLLAMA_CONTEXT_LENGTH=32768
OLLAMA_MAX_LOADED_MODELS=1
```

И скачайте веса:

```bash
make pull          # Ollama в Docker
make pull-native   # Ollama на хосте
```

Для лёгкого профиля всё делает bootstrap:

```bash
./scripts/bootstrap.sh --gpu --light
```

## Почему контекст по умолчанию 32K

Некоторые версии Qwen заявляют 256K и больше, но максимальная длина окна не означает,
что она бесплатна. KV-cache растёт вместе с контекстом, поэтому 256K легко съедает
десятки гигабайт дополнительной памяти. 32K — практичный старт. Повышайте постепенно:

```dotenv
OLLAMA_CONTEXT_LENGTH=65536
```

После изменения перезапустите Ollama:

```bash
docker compose -f compose.yaml up -d --force-recreate ollama
```

Для Kimi Code передайте такое же значение:

```bash
./scripts/kimi-local.sh --context 65536 .
```

## Проверка размещения

```bash
# Контейнерный режим
docker compose -f compose.yaml exec ollama ollama ps

# Native
ollama ps
```

`100% GPU` — модель полностью в VRAM. Если видите CPU/GPU split, уменьшите модель,
контекст, `OLLAMA_NUM_PARALLEL` или число одновременно загруженных моделей.

## Модели не работают одновременно — это нормально

В `.env.example` задано `OLLAMA_MAX_LOADED_MODELS=1`: при переключении из обычного
чата в vision Ollama выгружает одну модель и загружает другую. Это экономит память.
На машине с большим запасом можно поставить `2`, но потребуется примерно сумма
памяти обеих моделей плюс два KV-cache.

## Никакого дополнительного фильтра

Стек не добавляет moderation API или скрытый «цензурирующий» system prompt. Если
нужно изменить характер ответов, создайте собственный Modelfile либо задайте system
prompt в Open WebUI. Исходное поведение и ограничения всё равно зависят от весов
Qwen; название модели не является гарантией конкретных ответов.
