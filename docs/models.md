# Модели и системные требования

БРОДЯГА по умолчанию использует две официальные модели из библиотеки Ollama:

- `qwen3:8b` — текст, reasoning, код и tool calling;
- `qwen3-vl:8b` — изображения, скриншоты, документы и OCR.

Обе модели в стандартных тегах Ollama имеют квантизацию Q4_K_M. Qwen 3 VL требует
Ollama 0.12.7+, а pinned-образ проекта новее этого минимума.

## Размеры и практические профили

| Профиль | LLM | Вес | VLM | Вес | Практический минимум памяти* |
|---|---|---:|---|---:|---:|
| Tiny | `qwen3:1.7b` | 1.4 ГБ | `qwen3-vl:2b` | ~1.9 ГБ | 8 ГБ RAM / 4 ГБ VRAM |
| Light | `qwen3:4b` | 2.5 ГБ | `qwen3-vl:4b` | 3.3 ГБ | 16 ГБ RAM / 6–8 ГБ VRAM |
| Default | `qwen3:8b` | 5.2 ГБ | `qwen3-vl:8b` | 6.1 ГБ | 32 ГБ RAM / 10–12 ГБ VRAM |
| Strong | `qwen3:14b` | 9.3 ГБ | `qwen3-vl:8b` | 6.1 ГБ | 32–48 ГБ RAM / 16 ГБ VRAM |
| Power | `qwen3:30b` | 19 ГБ | `qwen3-vl:30b` | 20 ГБ | 64 ГБ RAM / 24+ ГБ VRAM |

\* Оценка дана для одной активной модели, одного запроса и контекста около 32K.
Это не официальная гарантия: кроме весов, память занимает KV-cache, vision encoder,
runtime и буферы. Если не хватает VRAM, Ollama выгружает часть слоёв в RAM, но
скорость заметно падает.

Актуальные точные размеры тегов: [Qwen 3](https://ollama.com/library/qwen3) и
[Qwen 3 VL](https://ollama.com/library/qwen3-vl).

## Как выбрать

- **Ноутбук/мини-ПК без GPU:** начните с `--light`; 4B заметно быстрее на CPU.
- **8 ГБ VRAM:** 4B почти всегда комфортнее; 8B может потребовать короткого контекста.
- **12 ГБ VRAM:** стандартные 8B — разумный баланс.
- **16 ГБ VRAM:** Qwen 3 14B + VL 8B, если модели не держатся одновременно.
- **24 ГБ VRAM:** 30B Q4 обычно помещается впритык; оставьте запас под KV-cache.
- **Apple Silicon:** ориентируйтесь на общую unified memory и используйте native Ollama.

## Сменить профиль

Отредактируйте `.env`:

```dotenv
QWEN_MODEL=qwen3:14b
VLM_MODEL=qwen3-vl:8b
OLLAMA_CONTEXT_LENGTH=32768
OLLAMA_MAX_LOADED_MODELS=1
```

И скачайте веса:

```bash
make pull          # Ollama в Docker
make pull-native   # Ollama на хосте
```

Для лёгкого профиля всё делает bootstrap:

```bash
./scripts/bootstrap.sh --gpu --light
```

## Почему контекст по умолчанию 32K

Некоторые версии Qwen заявляют 256K и больше, но максимальная длина окна не означает,
что она бесплатна. KV-cache растёт вместе с контекстом, поэтому 256K легко съедает
десятки гигабайт дополнительной памяти. 32K — практичный старт. Повышайте постепенно:

```dotenv
OLLAMA_CONTEXT_LENGTH=65536
```

После изменения перезапустите Ollama:

```bash
docker compose -f compose.yaml up -d --force-recreate ollama
```

Для Kimi Code передайте такое же значение:

```bash
./scripts/kimi-local.sh --context 65536 .
```

## Проверка размещения

```bash
# Контейнерный режим
docker compose -f compose.yaml exec ollama ollama ps

# Native
ollama ps
```

`100% GPU` — модель полностью в VRAM. Если видите CPU/GPU split, уменьшите модель,
контекст, `OLLAMA_NUM_PARALLEL` или число одновременно загруженных моделей.

## Модели не работают одновременно — это нормально

В `.env.example` задано `OLLAMA_MAX_LOADED_MODELS=1`: при переключении из обычного
чата в vision Ollama выгружает одну модель и загружает другую. Это экономит память.
На машине с большим запасом можно поставить `2`, но потребуется примерно сумма
памяти обеих моделей плюс два KV-cache.

## Никакого дополнительного фильтра

Стек не добавляет moderation API или скрытый «цензурирующий» system prompt. Если
нужно изменить характер ответов, создайте собственный Modelfile либо задайте system
prompt в Open WebUI. Исходное поведение и ограничения всё равно зависят от весов
Qwen; название модели не является гарантией конкретных ответов.
